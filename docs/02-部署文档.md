## 1. 前置条件

| 依赖 | 版本 | 检查命令 |
|---|---|---|
| JDK | **17 或更高** | `java -version` |
| Maven | 3.9+ | `mvn -v` |
| Docker | 20.10+（需能创建容器） | `docker ps` |

**Docker 必须真的能跑起来**，不只是装了 CLI：

```bash
docker ps        # 能输出表头（哪怕是空的）才算就绪
```

> 如果报 `failed to connect to the docker API`，说明守护进程没启动。
> Windows/macOS 上打开 Docker Desktop 等它就绪；Linux 上 `sudo systemctl start docker`。

### 国内网络：先配 Docker 镜像加速

**这一条几乎所有国内用户都会踩。** 默认情况下 `docker build` 会去 `auth.docker.io` 拉基础镜像，
而这个域名在国内通常连不上，表现为构建卡住然后报：

```
failed to fetch anonymous token: ... dial tcp ...: connectex: A connection attempt failed
```

**解决办法**：给 Docker 配一个国内镜像源。

Docker Desktop：`Settings` → `Docker Engine`，在 JSON 里加：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run"
  ]
}
```

改完点 `Apply & Restart`。或者不改配置，直接先把基础镜像拉下来再改个名：

```bash
docker pull docker.m.daocloud.io/library/eclipse-temurin:17-jdk-alpine
docker tag  docker.m.daocloud.io/library/eclipse-temurin:17-jdk-alpine eclipse-temurin:17-jdk-alpine
```

（第二种办法不需要重启 Docker，本项目实测就是这样绕过网络问题的。）

## 2. 第一步：构建运行镜像

**这个镜像是给"用户代码"用的，不是给执行器自己用的。** 两回事，别搞混。

```bash
cd code-executor
docker build -t code-executor-runner:1 .
```

本项目采用的**分层构建**，两个目标可以单独构建：

```bash
# 只要 JVM 的精简版（不含 Python/Node，攻击面更小）
docker build --target runner-base -t code-executor-runner-jvm:1 .

# 默认目标：JVM + Python + Node（全量）
docker build --target runner-polyglot -t code-executor-runner:1 .
```

构建完成后确认：

```bash
docker images | grep code-executor-runner
```

> **改了 `Dockerfile` 里的语言之后，记得同步改 `src/main/resources/languages.yml`**，
> 两边要对得上——镜像里有 `go` 但配置里没配，或者反过来，都会出问题。

## 3. 第二步：启动执行器

### 先准备一个 API Key

**鉴权默认开启，没有 key 会直接启动失败。** 先生成一个：

```bash
openssl rand -base64 32
```

再通过环境变量传入（不要写进 `application.yml`，更不要提交到 git）：

```bash
export EXECUTOR_AUTH_KEYS_0_NAME=my-app
export EXECUTOR_AUTH_KEYS_0_VALUE='<上面生成的串>'
mvn spring-boot:run
```

```powershell
# Windows PowerShell
$env:EXECUTOR_AUTH_KEYS_0_NAME = 'my-app'
$env:EXECUTOR_AUTH_KEYS_0_VALUE = '<上面生成的串>'
mvn spring-boot:run
```

> 这个环境变量名是 Spring Boot 的宽松绑定：下划线数字对应列表下标。
> 配第二个 key 就是 `EXECUTOR_AUTH_KEYS_1_NAME` / `_1_VALUE`。
>
> 只想本地跑着玩：`--executor.auth.enabled=false`。

看到这几行就说明起来了：

```
API Key 鉴权已开启：请求头=X-API-Key 已配置 1 个调用方 免鉴权路径=[/actuator/health]
Docker 客户端已配置：host=npipe:////./pipe/dockerDesktopLinuxEngine 连接超时=10s 响应超时=120s 最大连接=32
已加载 3 种语言（启用 3 种）：[java, python, javascript]
运行镜像已就绪：code-executor-runner:1
Tomcat started on port 8080 (http)
```

**特别注意"运行镜像已就绪"这一行。**
如果它变成 `找不到运行镜像：xxx，请先在项目根目录执行：docker build -t xxx .`，
说明第 2 步没做或镜像名对不上——执行器**依然会正常启动**，但所有执行请求都会返回 503。
这是刻意的设计：起不来的服务连一句有用的错误都告诉不了你。

### 打包成 jar 运行

```bash
mvn clean package
EXECUTOR_AUTH_KEYS_0_NAME=my-app \
EXECUTOR_AUTH_KEYS_0_VALUE='<你的key>' \
java -jar target/code-executor-0.1.0.jar
```

### 没有 Docker？用演练模式

```bash
mvn spring-boot:run -Dspring-boot.run.arguments=--executor.dry-run=true
```

这时**不会创建任何容器**，接口会把"将会下发给 Docker 的命令"原样渲染出来。
适合先看懂流程，或者本机就是没有 Docker 的情况。

## 5. 配置项全表

全部在 `src/main/resources/application.yml` 的 `executor.*` 下，也可以用命令行参数覆盖：

```bash
java -jar code-executor-0.1.0.jar --executor.max-concurrent-executions=8
```

### 核心配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `executor.auth.enabled` | `true` | API Key 鉴权。**没有配置 key 时启动失败** |
| `executor.auth.header-name` | `X-API-Key` | 从哪个请求头取 key |
| `executor.auth.keys[n].name` / `.value` | 空 | 调用方凭据。支持多个，用于 key 轮换 |
| `executor.auth.public-paths` | `[/actuator/health]` | 免鉴权路径（Ant 风格） |
| `executor.image` | `code-executor-runner:1` | 运行用户代码的镜像名 |
| `executor.dry-run` | `false` | 演练模式，不创建容器 |
| `executor.user` | `10001:10001` | 容器内运行代码的用户，**必须是镜像里存在的非 root 用户** |
| `executor.max-code-bytes` | `65536` | 单次提交代码上限。⚠️ 不要超过 90 KB，见下方说明 |
| `executor.max-output-bytes` | `65536` | stdout / stderr **各自**的上限 |
| `executor.max-concurrent-executions` | `4` | 并发上限，超出返回 429 |
| `executor.workspace-size-mb` | `64` | 容器工作目录（tmpfs）大小 |
| `executor.tmp-size-mb` | `16` | 容器 `/tmp`（tmpfs）大小 |
| `executor.container-lifetime-slack-seconds` | `30` | 容器"保命时长"的余量 |

> ⚠️ **`max-code-bytes` 有隐藏上限**：源码是以 base64 形式作为一个命令行参数传进容器的，
> 而 Linux 单个参数上限是 128 KiB（`MAX_ARG_STRLEN`）。
> base64 会膨胀 1/3，所以代码上限**不要超过 90 KB**。
> 超过时接口会返回 400 并说明原因，不会静默失败。

### Docker 连接

| 配置 | 默认 | 说明 |
|---|---|---|
| `executor.docker.host` | 空 | 留空 = 走 `DOCKER_HOST` 或默认 socket |
| `executor.docker.connect-timeout-seconds` | `10` | 建立连接超时 |
| `executor.docker.response-timeout-seconds` | `120` | 单次 API 响应超时 |
| `executor.docker.max-connections` | `32` | 连接池大小 |

常见 host 写法：

| 平台 | 值 |
|---|---|
| Linux / macOS | `unix:///var/run/docker.sock` |
| Windows（Docker Desktop） | `npipe:////./pipe/dockerDesktopLinuxEngine` |
| 远程 Docker（需 TLS） | `tcp://1.2.3.4:2376` |

### 孤儿容器回收

| 配置 | 默认 | 说明 |
|---|---|---|
| `executor.reaper.enabled` | `true` | 是否开启 |
| `executor.reaper.interval-millis` | `60000` | 扫描间隔（毫秒） |
| `executor.reaper.grace-seconds` | `120` | 创建后多久才允许被回收。**必须大于最长的一次执行** |

### 语言配置

见 [`src/main/resources/languages.yml`](../src/main/resources/languages.yml)。
**加一门语言只需要改这个文件，不用改 Java 代码**——但要同时在 Dockerfile 里把语言装上。

## 6. 生产部署

### systemd 服务（Linux，推荐）

执行器**直接跑在宿主机上**，不要容器化（原因见第 7 节）。

`/etc/systemd/system/code-executor.service`：

```ini
[Unit]
Description=Code Executor
After=docker.service
Requires=docker.service

[Service]
Type=simple
User=code-executor
WorkingDirectory=/opt/code-executor
# 密钥通过环境变量注入，不要写进 unit 文件（unit 文件是可读的）
EnvironmentFile=/etc/code-executor/env
ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/code-executor/code-executor-0.1.0.jar
Restart=always
RestartSec=5

# 基础加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/code-executor

[Install]
WantedBy=multi-user.target
```

`/etc/code-executor/env`（权限设成 `600`，属主 `root`）：

```bash
EXECUTOR_AUTH_KEYS_0_NAME=my-app
EXECUTOR_AUTH_KEYS_0_VALUE=<openssl rand -base64 32 生成>
```

```bash
sudo install -d -m 750 /etc/code-executor
sudo install -m 600 /dev/null /etc/code-executor/env
sudo editor /etc/code-executor/env
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now code-executor
sudo journalctl -u code-executor -f
```

> 注意服务用户 `code-executor` 需要能访问 Docker socket
> （加入 `docker` 组：`sudo usermod -aG docker code-executor`）。

### 上线前检查清单

- [ ] 运行镜像已构建，且名与 `executor.image` 一致
- [ ] `executor.max-concurrent-executions` 按机器规格算过（**别照抄默认的 4**）
- [ ] `executor.reaper.grace-seconds` **大于**最长的一次执行总时长
- [ ] 执行器和 Docker **不在同一台机器上跑主业务和数据库**
- [ ] **API Key 已通过环境变量注入**（不是写在配置文件里），且长度 ≥ 16 位
- [ ] **前面有反向代理终止 HTTPS**（本服务只跑 HTTP，key 明文会暴露）
- [ ] 防火墙限制来源，只放行可信调用方（见第 7 节）
- [ ] JVM 堆（`-Xmx`）和执行器自身的内存占用留足余量
- [ ] 磁盘：容器层会占空间，定期 `docker system prune`

### 调优建议

| 现象 | 调整方向 |
|---|---|
| 大量 429 | 提高 `max-concurrent-executions`，但先确认内存够 |
| 编译型语言经常超时 | 调大对应语言的 `compile-timeout-ms` |
| 容器启动慢 | M1 路线图里的容器池；短期可减少镜像层数 |
| 内存吃紧 | 降低 `max-concurrent-executions`，或降低各语言 `memory-mb` |

## 7. ⚠️ 一个必须知道的安全红线

### 鉴权默认开了，但它是静态共享密钥

`executor.auth.enabled` 默认 `true`，没配 key 就起不来。但它有明确的边界，别把它当成一套身份体系：

| 它做到了 | 它没做到 |
|---|---|
| 拦住没有 key 的调用 | **所有持有同一 key 的调用方在服务端是同一个身份** |
| 校验失败不泄露 key（连前缀都不记日志） | 没有过期时间 |
| 支持多 key 以支持轮换 | 没有自动轮换 |
| 用常量时间比较，防时序攻击 | 没有按 key 的配额（一个 key 打满，其他一起受影响） |
| —— | **不做 TLS**：服务只跑 HTTP，必须由反向代理终止 HTTPS，否则 key 在网络上是明文 |

### 不要把执行器容器化，然后给它挂 `/var/run/docker.sock`

这是这类项目最常见、也最致命的部署错误：

```yaml
# ❌ 绝对不要这样做
services:
  executor:
    image: code-executor:1
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock   # ← 这一行等于把宿主机 root 交出去
```

**为什么致命？** 能访问 `docker.sock` 的人，可以让 Docker 以 root 身份
启动一个挂载宿主机根目录的容器，然后读写宿主机上的任意文件。
也就是说：

> 谁能让执行器创建一个容器，谁就等同于拥有宿主机的 root 权限。

而鉴权只能拦住"没有 key 的人"。**拿到 key 之后，调用方依然可以让执行器创建容器，
依然等价于宿主机 root**——鉴权缩小的是"谁能进来"，不是"进来之后能干什么"。

**正确做法**：

1. 执行器作为普通进程直接跑在宿主机上（见上面的 systemd 配置）
2. 用防火墙 / 安全组限制只有可信来源能访问 8080
3. 至少跑在**独立于主业务和数据库**的机器上
4. 有条件的话，把执行器放在一台专门用来跑用户代码的机器上——
   这样即使被攻破，损失也只限于这台机器

## 8. Windows 用户注意

### 控制台中文乱码

如果日志里的中文显示成 `�Ѽ���`，那是**控制台代码页**的问题，不是服务的问题
（接口返回的 JSON 是标准 UTF-8）。执行一次：

```powershell
chcp 65001
```

### PowerShell 脚本报"意外的标记"

如果运行 `scripts/e2e-test.ps1` 时报：

```
表达式或语句中包含意外的标记"[PASS]"
```

说明脚本文件的 **UTF-8 BOM 丢了**。Windows PowerShell 5.1 在没有 BOM 时会按
本地编码（GBK）读 `.ps1`，中文注释就会把语法搞乱。修复：

```powershell
$p = 'scripts\e2e-test.ps1'
$c = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($p, $c, [System.Text.UTF8Encoding]::new($true))
```

### Docker Desktop 的网络

Docker Desktop 用的是 `dockerDesktopLinuxEngine` 这个 pipe，
`executor.docker.host` 留空它会自动探测到，不用手动配。

## 9. 故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 启动日志：`连不上 Docker` | 守护进程没启动 | 启动 Docker Desktop / `systemctl start docker` |
| 启动日志：`找不到运行镜像` | 没构建或名字不对 | `docker build -t code-executor-runner:1 .` |
| `docker build` 卡住/超时 | 拉不到基础镜像 | 配国内镜像加速，见第 1 节 |
| 请求返回 **401** | 缺少或错误的 `X-API-Key` | 检查环境变量 `EXECUTOR_AUTH_KEYS_0_VALUE` 有没有真的传进进程 |
| 启动失败：**没有配置任何 key** | 鉴权开着但没配 key | 配一个 key，或临时 `--executor.auth.enabled=false` |
| 启动失败：**至少需要 16 位** | key 太短 | `openssl rand -base64 32` 重新生成 |
| 启动失败：**class file version 61.0** | Maven 用的是 JDK 11 | `JAVA_HOME` 指向 JDK 17（`java -version` 确认） |
| 请求返回 **503** | Docker 不可用或镜像缺失 | 响应体的 `message` 会写明具体原因（连不上 / 镜像找不到） |
| 请求返回 **429** | 并发满了 | 调大 `max-concurrent-executions`，或调用方退避重试 |
| 请求返回 **400** | 语言不支持 / 代码为空 / 超长 / JSON 格式错 | 看响应体的 `message` |
| 所有请求都 `TIMEOUT` | 用户代码里有域名解析（见下） | 正常现象，见下方说明 |
| 容器跑完不消失 | 清理失败 | 回收器会在 `grace-seconds` 后处理；看 WARN 日志 |
| 磁盘越来越小 | 容器层累积 | `docker system prune`，并检查回收器是否在跑 |
| 日志中文乱码 | 控制台代码页 | `chcp 65001` |

### 为什么"域名解析"会导致 TIMEOUT 而不是报错？

因为 `--network none` 之后，Docker **仍然**会把一个 nameserver 写进容器的
`/etc/resolv.conf`，但那个地址根本路由不到。
用户代码里只要有 `socket.gethostbyname(...)` 之类的调用，
解析就会一直重试到耗尽运行超时。

**这是符合预期的**（"解析不出来"就说明确实出不去网），
只是错误信息表现为 `TIMEOUT` 而不是 DNS 错误。

本项目已经把容器的 DNS 指向 `127.0.0.1`，主要是为了**不把宿主机的内部 DNS 地址
泄露给用户代码**——但 musl（Alpine）的重试节奏拦不住，解析仍然会阻塞到超时。

如果这影响体验，可以在镜像里把 `/etc/resolv.conf` 做成只含 `options timeout:1 attempts:1`，
或者干脆在文档里告诉用户"别做 DNS 解析"。
